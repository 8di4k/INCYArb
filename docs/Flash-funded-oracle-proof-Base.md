# Base: полный flash-funded круг с положительным историческим расчётом

**Полный круг с бесплатным v4-финансированием, возвратом долга и выплатой
воспроизведён с положительным остатком после расчётных расходов. Регулярная
доходность нашей торговли и рынок от $100/сутки этим пока не доказаны.**

Продолжение [первичной проверки Elfomo/Biconomy](Oracle-pair-repeatability-Base.md).
Все времена ниже — **23 октября 2026, Москва (UTC+3)**. Исследование относится
к Base, не подтверждает наличие этих площадок на Ink и не меняет целевую
стратегию на AMM-only.

## Что изменилось в проверке

Вместо предоставления 100 USDC через token storage override наш
[диагностический контракт](validation/flash-funded-oracle/FlashPairProbe.sol)
начинает с **нулём USDC и WETH**. В одном `eth_call` он выполняет:

1. `PoolManager.unlock` и `take` нужной валюты.
2. Обмены Elfomo ↔ Biconomy с фактическими передачами токенов.
3. `sync → transfer → settle` ровно на сумму долга.
4. Проверку восстановления исходного баланса PoolManager и отсутствия
   промежуточного остатка.
5. Проверку минимальной прибыли, выплату полученного остатка отправителю и
   проверку увеличения его баланса.

Проверены два стартовых актива и два пути Biconomy. Лучший проверенный вариант:
**WETH из v4 → Biconomy direct fill → USDC → Elfomo → WETH → возврат v4**.
Это круг между двумя propAMM; источник расхождения именно в задержке двух
оракульных публикаций отдельно не установлен.

Base PoolManager `0x498581ff718922c3f8e6a244956af099b2652b2b` подтверждён
[официальными deployments Uniswap](https://developers.uniswap.org/docs/protocols/v4/deployments).
По [документации Biconomy на закреплённом commit](https://github.com/bcnmy/propamm-protocol-docs/blob/5eeca232d7ccd1f4f66ee5f33932ad6660a1571c/docs/aggregator-api.md)
`fill` открыт для taker без отдельной RFQ-подписи. Его фактическое исполнение
проверено с синтетическими caller/tx.origin. Maker
`0x960f1e3181e928210c02a34ee29bf3d354dd2ff5` выбран из onchain `makers/board`.

Разрешённые overrides: только код синтетического исполнителя и ETH-баланс
отправителя для оплаты газа. Код/балансы PoolManager, токенов, venues и maker,
их цены, лимиты и allowance не подменяются. Approval Elfomo, комиссия обменов,
заём, возврат и выплата входят в симуляцию и оценку газа.

## Конкретный положительный результат

Состояние блока **52959338**, **01:27:03**:

| Компонент | Значение |
| --- | ---: |
| Заём и возврат | 0,06335 WETH |
| Собственный стартовый капитал контракта | 0 USDC, 0 WETH |
| Остаток после возврата, выплаченный отправителю | 0,000005579782895095 WETH |
| Газ с новым получателем без прежнего остатка WETH | 554 629 gas |
| Лимит с запасом 20% | 665 555 gas |
| Base fee / tip | 0,005 / 0,001 gwei |
| L2-бюджет по полному лимиту | 0,00000399333 ETH |
| L1 upper estimate для данного envelope | 0,000000001354827497 ETH |
| Operator fee | 0 |
| Итоговый бюджет расходов | 0,000003994684827497 ETH |
| **Разница после бюджета расходов** | **+0,000001585098067598 ETH** |

WETH оценивается 1:1 в ETH; выплата остаётся WETH. Здесь нет пересчёта по
сторонней долларовой цене. Превращение выплаты в USD-стейбл или отдельное
разворачивание WETH потребует своей операции и расходов.

Это оценка гипотетической транзакции на историческом состоянии, не receipt
реально отправленной сделки. Используется fee cap = pinned base + tip;
повышение base fee может сделать транзакцию непринимаемой. L1 upper estimate —
оценка GasPriceOracle, не гарантия будущих расходов. Deployment, обслуживание,
доставка, неудачные попытки и конкуренция не включены в периодный результат.
Вызов дополнительно повторён с указанным gas limit и EIP-1559 fee caps;
выход совпал. Это состояние конца блока: цены, время, номер блока и лимиты
при последующем включении могут измениться.

## Почему результат улучшился

На том же блоке для размера около 150 USDC:

| Исполнение | Измеренный gas estimate |
| --- | ---: |
| Заём USDC, Biconomy через общий venue | 673 945 |
| Заём USDC, Biconomy direct fill | 551 690 |
| Заём WETH, Biconomy через общий venue | 659 541 |
| Заём WETH, Biconomy direct fill | 537 287 |

Эта матрица использует отправителя с уже существующим небольшим остатком WETH.
Основной результат выше дополнительно перечитан с новым отправителем:
его первая выплата дороже. Два разных адреса исполнителя и два новых
отправителя дали одинаковый token output; исходный код этих адресов пуст.

Сам бесплатный заём не создаёт спред. Выигрыш дали корректный объём, направление
заимствования и более дешёвый публичный путь исполнения. Экономить на возврате,
проверке прибыли или выплате для получения положительного расчёта не пришлось.

## Проверка повторного появления

До чтения новых котировок выбран сплошной последующий диапазон
**52960000–52960299**, **01:49:07–01:59:05**, 300 блоков без пропусков.
Для каждого выполнялся весь круг с займом **0,063 WETH** и tip **0,001 gwei**.

- 285 вызовов дали `Shortfall`: остатка не хватает для возврата долга,
  поэтому транзакция целиком откатывается.
- 15 вызовов вернули долг и оставили положительный WETH до газа.
- После L2/L1/operator fee и 20% запаса газа положительны **два соседних
  снимка**: 52960086 и 52960087, в 01:51:59 и 01:52:01.
- Все 300 hash повторно проверены; для 15 расчётов расходов hash также
  перепроверен после чтения GasPriceOracle.

Это повторное появление положительного исторического состояния примерно через
25 минут после исходного случая. Два соседних снимка **не считаются двумя
независимыми заработками**. Каждый `eth_call` начинает с canonical state без
наших прежних сделок; влияние собственного исполнения на последующие блоки и
восстановление доступного объёма после него не проверены.

Положительные снимки дополнительно повторены с новым получателем и полной
оценкой его первой выплаты:

| Состояние блока | Остаток после консервативного бюджета, ETH |
| --- | ---: |
| 52960086 | +0,000000826808710147 |
| 52960087 | +0,000004530381605458 |

См. `cold-window-positives.json.gz` в архиве.
Десятиминутный диапазон и один размер не дают оценку $/сутки, оптимального
размера на каждом блоке или общесетевой частоты возможностей.

## Ограничения, подтверждённые исполнением

- Onchain board на проверенных трёх блоках показывает `remaining = 0,06335 WETH`.
  150 USDC проходят; 151 USDC и большие проверенные размеры на лучшем блоке
  откатываются. Лимит определяется площадкой, не балансом flash-источника.
- Второй круг по 0,06335 WETH в том же `unlock` откатывается на втором
  Biconomy fill. Простое повторение сделки не умножает доход.
- Два меньших круга по 0,03 WETH укладываются в лимит, но требуют больше газа;
  пакетирование не стало лучшим проверенным вариантом.
- При tip 0,01 gwei тот же gross уже не покрывает бюджет расходов.
- Завышенный `minimumProfit` откатывает круг; чужой вызов `unlockCallback`
  отклоняется. Чужие RFQ, права доступа и подписи не использовались.

Все успешные симуляции получены через `https://mainnet.base.org`.
Попытка независимого чтения через второй RPC получила HTTP 403; независимый
локальный EVM replay этих venues не проводился. Исходники/исторические
implementations сторонних venues независимо не пересобирались.

## Воспроизведение и решение

```bash
python scripts/probe_flash_pair.py --solc /path/to/solc-0.8.28 \
  --start-block 52959338 --end-block 52959338 \
  --amount-weth-raw 63350000000000000 \
  --output data/flash-pair-proof.json.gz
```

[Manifest и SHA-256](validation/flash-funded-oracle/manifest.json) связывают
исходник, матрицу размеров/маршрутов, repayment/control/fee ответы,
сплошной диапазон и повторные проверки. Скрипт компилирует наш исходник,
проверяет chain ID, ancestry и повторные hash, сохраняет overrides, calldata,
unsigned envelope, raw responses и все компоненты расходов. Неизвестная
обязательная комиссия не превращается в нулевую.

**Подтверждено:** полный flash-funded круг и положительная историческая оценка
после всех моделируемых сетевых расходов; положительные состояния появились
и в отдельном последующем диапазоне.

**Не подтверждено:** получение этого результата при реальном включении,
повторяемая торговля после собственных fills, прибыль за 1–2 дня с откатами
и достижимость $100/сутки. Это основание для дальнейшей read-only проверки,
а не квалификация live-запуска.
